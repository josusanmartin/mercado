# Brief: `api` (API / MPP engineer)

You own `apps/web/app/api/**`, `apps/web/lib/server/**`, `apps/web/lib/mpp/**`, `fixtures/**`, and `packages/shared/src/{schemas,types}.ts`. Route shapes are in INTERFACES.md.

1. **Shared schemas** first: Zod schemas and TS types for every route in `packages/shared/src/schemas.ts`/`types.ts`, re-exported from `packages/shared/src/index.ts` (coordinate that file with `@contracts`). Post in the channel when they land so `@web` can code against them.
2. **Fixtures**: `fixtures/uber/{steady,irregular,new-driver}.json`, deterministic, 8–12 weeks each (weekly gross/net MXN, trips, active hours, payments), each carrying `"label": "Demo Uber Data"`, `"demo": true`. Steady should be eligible, irregular eligible with a smaller cap, and new-driver ineligible (too few weeks).
3. **Credit service** (`lib/server/credit/`): an `EarningsProvider` interface (`getDriverProfile`, `getTrips`, `getPayments`) plus `DemoEarningsProvider`, with a `UberEarningsProvider` stub that documents the OAuth scopes and restricted approval and throws. Use a deterministic score from median weekly net, volatility (CV), active weeks and trip consistency, with features and a plain-language explanation logged. Cap = min(15% of median weekly net, 1,500 MXN), subject to a score floor (and pool liquidity if readable). Sign EIP-712 `Eligibility(address borrower,uint256 maxAmount,uint256 expiry,uint256 nonce,bytes32 dataHash)` with `ATTESTATION_SIGNER_PRIVATE_KEY` (viem), domain `MercadoCreditPool`/`1`/42431/pool address. Use a short expiry (~15 min), random 256-bit nonces, and `dataHash` = keccak256 of the canonical JSON of the income report. Routes: `/api/driver/demo`, `/api/driver/score`.
4. **FX**: `/api/fx` reads the on-chain oracle (address from deployments json via `@mercado/shared`), falls back to a config value before deploy, and always labels `isMock`/source.
5. **MPP bills** (the most important real piece): study https://mpp.dev and the installed `node_modules/mppx` source (`mppx/server`, `Mppx.create`, the Tempo charge method, and `mppx/client`). `POST /api/bills/quote` and `POST /api/bills/pay` should return a **real 402 challenge** bound to amount and order when unpaid, verify the payment credential/receipt on-chain on retry, then call the `BillProvider` (`quote/execute/getStatus`; `MockTelcelProvider`, optional `MockCFEProvider`, `ArcusProvider` stub) and return a believable reference with `simulated: true` and the SIMULATED label. Orders persist in `.data/orders.json` (gitignore it) with an idempotency key and the state machine `CREATED → PAYMENT_VERIFIED → FULFILLED_SIMULATED | FAILED(paidButUnfulfilled)`. Retries never fulfill twice. Recipient is `MERCHANT_ADDRESS`; token is xMXN (until it's deployed, use whatever Tempo testnet token works and swap later). Also `GET /api/bills/orders/[id]`.
6. **Client helper** for `@web`: `apps/web/lib/mpp/client.ts`, a function that takes a viem account/wallet client and does the 402 → pay → retry dance via `mppx/client`, returning `{ order, receipt }`. Show `@web` how to call it.
7. **Tests** (vitest): score determinism, signature recovers to the signer, expired/ineligible paths, 402 on unpaid, idempotent retry, no double fulfillment. Curl-check the 402 against the live dev server.
8. Stretch: make `/api/driver/score` itself an MPP-paid endpoint for third-party underwriters (keep a free path for the app).
