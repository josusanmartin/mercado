# Brief: `web` (frontend engineer)

You own `apps/web/**` except `apps/web/app/api/**`, `apps/web/lib/server/**` and `apps/web/lib/mpp/**` (those belong to `api`). The Next.js app is already scaffolded (App Router, TS, Tailwind). `viem`, `wagmi`, `@tanstack/react-query`, `zod` and `mppx` are being installed by lead; check `apps/web/package.json`.

1. **Start the dev server** in its own tmux window: `tmux new-window -d -t mercado -n dev -c /home/josu/dev/mercado "npm run dev -w apps/web; bash"` (port 3100). Post in the channel when it's up. You own keeping it alive.
2. **Shell + design.** Load the `frontend-design` skill and add shadcn/ui. Build a polished, mobile-responsive dashboard: a persistent "Testnet prototype, not a real financial product" banner, a network badge (Tempo Moderato 42431), and tabs **Home, Create pesos (/mint), Send money (/send), Get an advance (/credit), Pay bills (/pay), Earn (/earn)**, plus a contracts/addresses page with explorer links. Aim for a 2–3 minute recorded walkthrough: clear, confident, Mexico-flavored but professional.
3. **Wallets.** wagmi with the Tempo chain from `@mercado/shared` (`packages/shared/src/chain.ts`, owned by `contracts`; use a local placeholder until it lands). Support an injected wallet **and** a one-click **Demo Tour** with persona accounts (LP, Sender, Recipient, Driver, Lender) from testnet demo keys exposed via `NEXT_PUBLIC_DEMO_*` env in `apps/web/.env.local`. Copy them from the root `.env.local`, and clearly label them as testnet demo keys. The Demo Tour walks SPEC §0 steps 1→6 in order.
4. **Screens** per SPEC §3, coded against the ABIs/interfaces in INTERFACES.md (`packages/shared/src/abi/*` once `contracts` exports them). Every tx shows status plus an explorer link. Create pesos: deposit, FX quote (from `/api/fx`, labeled mock oracle), mint amount, projected ratio, stress indicator, repay/withdraw. Send: quote, swap with minOut, transfer to recipient ("onchain delivery only, no SPEI cash-out"). Advance: demo driver connect (`/api/driver/demo`, "Demo Uber Data" label), weekly income chart (simple SVG/recharts, no custom framework), why-offered explanation, draw/repay with the attestation from `/api/driver/score`. Pay bills: Telcel airtime (CFE optional), checkout via the MPP client helper `api` provides in `apps/web/lib/mpp/`, with separate payment vs fulfillment statuses and the "SIMULATED" label. Earn: supply/withdraw, pool stats, realized fees, no APY promises. Home: balances, collateral health, loan, recent receipts.
5. Handle errors gracefully (wrong chain, insufficient balance, reverts with readable reasons, stale oracle).
Coordinate with `@api` on response shapes and the MPP client helper, and with `@contracts` on ABIs/addresses. Mock data is fine to start; switch to real calls as soon as addresses land.
